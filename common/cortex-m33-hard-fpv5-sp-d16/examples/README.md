# Example firmware — cortex-m33-hard-fpv5-sp-d16

Generated by lib-build for target `arm-none-eabi` (`--target=arm-none-eabi -mcpu=cortex-m33 -mfloat-abi=hard -mfpu=fpv5-sp-d16`).

This is a **starting point**, not a complete runnable firmware. It gives you
the minimum pieces needed to satisfy the picolibc + libc++ runtime contract.
You still need to plug in
two things before it can boot:

1. Edit [`memory.ld`](memory.ld) — change the `MEMORY { flash, ram }` block
   to your chip's real flash and RAM origin / length.
2. Edit [`src/startup.c`](src/startup.c) — append your chip's peripheral IRQ
   handlers to the end of `g_pfnVectors[]`. The core exception entries
   (Reset, NMI, HardFault, SysTick, ...) are already wired.

Optional:

- [`src/syscalls.c`](src/syscalls.c) has a `board_putc` weak stub. Implement
  it (or override it in a UART driver file) so `printf` actually produces
  output. You also need to wire `clock_gettime()` to a real monotonic time
  source if you use `std::chrono::steady_clock`.
- [`src/libcpp_threads.c`](src/libcpp_threads.c) is only a placeholder for
  libc++'s external threading contract. If your firmware uses an RTOS, or if
  any code path depends on per-thread state or TLS, replace it with a complete
  port of the required `__libcpp_*` hooks.

## Build

```bash
cmake -B build -G Ninja -DCMAKE_TOOLCHAIN_FILE=./toolchain.cmake
cmake --build build
```

Artifacts:

- `build/firmware.elf` — the ELF you flash / debug.
- `llvm-size` output printed at the end of `cmake --build` tells you how
  much of flash / RAM you've used.

## Layout

```text
.
├── CMakeLists.txt          generated, edit if you add source files
├── toolchain.cmake         generated, defines the clang cross setup
├── memory.ld               ← EDIT: MEMORY block
└── src/
    ├── main.cpp            sample; replace with your app
    ├── startup.c           ← EDIT: peripheral IRQ table
    ├── syscalls.c          ← ADAPT: board I/O, heap boundary, monotonic clock
    └── libcpp_threads.c    ← ADAPT: scheduler / RTOS / TLS model
```

See `../USING.md` in the SDK root for a full walkthrough of the symbol
and section contract this template satisfies.
